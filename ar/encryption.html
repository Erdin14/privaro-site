Inside the encryption

An interactive demo

See what encrypted really means.

Step through it at your own pace. Your browser does the real thing to the photo you see here: AES-256-GCM, the cipher Privaro uses. Nothing leaves this page.

A simplified demo of the principle. It isn’t the app’s code or its file format. What’s simplified

Step 1 of 8

It starts out readable.

A photo is a file like any other. Any app that can reach it can open it, and so can anyone who picks up your phone while it’s unlocked.

Step 2 of 8

First, a key.

A key is 256 bits: ones and zeros, picked at random by the device. Privaro makes its key once, on your iPhone, and it stays there.

That’s the whole key. Each dot is one bit: filled for a one, empty for a zero. There are 2²⁵⁶ possible keys, a number 78 digits long.

Step 3 of 8

Then the photo, piece by piece.

The photo is cut into pieces. Each one is locked with the key, using AES-256-GCM, and each gets a seal of its own.

Twelve pieces, each locked and sealed on its own. What was a photo is now ciphertext.

Step 4 of 8

This is ciphertext.

It’s the same photo, encrypted. Nothing is blurred or covered up: every pixel has been replaced by the cipher’s output, which looks like random noise. Without the key, there is nothing in it to recognise.

Step 5 of 8

Only this is stored.

The encrypted file is all that goes into the vault. The key is kept apart from it, in the iPhone’s Keychain, and Privaro uses it only after Face ID or your passcode.

Step 6 of 8

Another key opens nothing.

Suppose someone tries a different key. It’s every bit as random as the real one. It just isn’t the one this photo was locked with.

Rejected. The cipher’s own check fails on the very first piece, and nothing comes back. Not a blurry version, not a corner of the photo.

Step 7 of 8

Change one bit, and it shows.

Now suppose someone gets at the stored file and alters it. Not by much: a single bit, out of more than four million.

Done. The ring marks the spot. To the eye, nothing looks different.

Refused. The piece with the changed bit no longer matches its seal, so nothing is opened. You never get a quietly damaged photo. The demo puts the bit back when you continue.

Step 8 of 8

With the right key, it comes back. Exactly.

The real key checks every piece’s seal and unlocks it. All twelve have to pass before the photo is shown.

Identical to the original, bit for bit. The demo checked: a SHA-256 fingerprint taken before encrypting matches the photo it has now.

In short

That’s the principle.

On your iPhone, Privaro does this to every photo and video you put in the vault, with more around it: the Keychain, Face ID, and iOS’s own file protection.

How it’s explained

The demo works on the photo’s pixels: 360 by 540 of them, three bytes each. That is 583,200 bytes of plaintext.

32 bytes from crypto.getRandomValues(). It’s shown only because it’s a throwaway: a real key is never displayed.

File ID. 128 random bits, new for every file.

File key. HKDF-SHA256 of the vault key and the file ID, held as an AES-256-GCM key this page can use but not read back.

Pieces. 12 pieces of 48,600 bytes: 45 rows of pixels each. Every piece is sealed under a fresh random 96-bit nonce. Its 128-bit tag also covers the file’s header and the piece’s position, so a piece can’t be changed, dropped or moved unnoticed.

A simplified demo.

It runs entirely in your browser, on a sample photo or one of your own, to show the principle. It is not a copy of Privaro’s storage system, and none of it is the app’s own code.

  • Same cipher, different engine. The app uses Apple’s CryptoKit; this page uses your browser’s Web Crypto. Both do AES-256-GCM, with a key for each file derived by HKDF-SHA256.
  • Smaller pieces. The app encrypts a file in pieces of 1 MB. Here the photo is cut into 12 small ones, so you can watch them.
  • Pixels, not a file. The demo encrypts the picture’s pixels, so the result can be drawn where the photo was. The app encrypts the photo or video file itself, and its thumbnail, name and caption separately.
  • The key isn’t protected here. It sits in this page’s memory and is shown on screen. In the app it’s kept in the iOS Keychain and never shown.
  • Unlock is only a button. In the app it’s Face ID, Touch ID or your Privaro passcode.
  • Its own file layout. A file made here can’t be opened by Privaro, or the other way round.
  • No promises about memory. When the demo is done with the photo or a key, it stops using them. That is not secure erasure: a web page can’t guarantee what a browser keeps in memory.
