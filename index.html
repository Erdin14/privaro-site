Privaro

A vault only you can open.

Privaro is a vault for the photos and videos on your iPhone. What you put in it is encrypted on the phone itself and only opens with Face ID or Privaro’s own passcode. There’s no account, and nothing is uploaded.

How to explain it

  1. A photo anyone can read

    It starts as an ordinary picture. Any app that gets to the file can show it.

  2. A key, made on the device

    256 random bits. Privaro makes its key once, on your iPhone, and the key stays on it.

  3. Encrypted, piece by piece

    Each piece of the photo is locked with the key, using AES-256. What comes out looks like random noise.

  4. Stored in the vault

    Only the encrypted file is kept. The key is kept apart from it, in the iPhone’s Keychain, and Privaro uses it only after Face ID or your passcode.

  5. Opened again, exactly

    With the right key every piece is checked, then unlocked. A wrong key or a changed file opens nothing.

Where it runs
In this tab, with your browser’s Web Crypto API. No request is made: watch your browser’s network inspector, or go offline and run it again. This site’s Content Security Policy has no connect-src, so the browser refuses any fetch, XHR or WebSocket call from its scripts.

File ID
128 random bits, new for every file.
File key
HKDF-SHA256 of the vault key and the file ID, held as an AES-256-GCM key this page can use but not read back.
Pieces
12 pieces of 48,600 bytes: 45 rows of pixels each. Every piece is sealed with AES-256-GCM under a fresh random 96-bit nonce. Its 128-bit tag also covers the file’s header and the piece’s position, so a piece can’t be changed, dropped or moved unnoticed.

What’s simplified
  • Same cipher, different engine. The app uses Apple’s CryptoKit; this page uses your browser’s Web Crypto. Both do AES-256-GCM, with a key for each file derived by HKDF-SHA256.
  • Smaller pieces. The app encrypts a file in pieces of 1 MB. Here the photo is cut into 12 small ones, so you can watch them.
  • Pixels, not a file. The demo encrypts the picture’s pixels, so the result can be drawn where the photo was. The app encrypts the photo or video file itself, and its thumbnail, name and caption separately.
  • The key isn’t protected here. It sits in this page’s memory, is shown on screen, and is gone when you leave. In the app it’s kept in the iOS Keychain and never shown.
  • Unlock is only a button. In the app it’s Face ID, Touch ID or your Privaro passcode.
  • Its own file layout. A file made here can’t be opened by Privaro, or the other way round.

What if someone else wants in?

Included with Pro

  • Decoy vault

    Set a second passcode that opens a separate vault with harmless photos in it. If you’re ever pushed to unlock Privaro, enter that one, and your real vault stays out of sight.

  • Duress wipe

    Set a passcode that erases the whole vault, decoy included, the moment it’s entered. It’s meant for the worst case, and it can’t be undone.

  • Break-in capture

    If someone enters the wrong passcode, Privaro can silently take a photo with the front camera and log the attempt with a timestamp, so you know if anyone has tried to get into your vault.
